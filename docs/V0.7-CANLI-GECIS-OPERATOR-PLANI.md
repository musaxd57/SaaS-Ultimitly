## 0. Bugünkü gerçek (2026-09-07, prod sayımı)
- `ChannelConnection` tablosu **boş**: prod'da hiçbir org'un DB'de Hospitable token'ı yok.
- Lale (kurucu org, `PRIMARY_ORG_ID`) **env fallback** ile çalışıyor (`HOSPITABLE_API_TOKEN`). Ayarlar
  "Sistemin ortak (env) Hospitable bağlantısı kullanılıyor" der; kod hazırlığından sonra bu durum
  `state: env_fallback` olarak açıkça görünür.
- Lale'nin Hospitable aboneliği 402 (veri donuk). Bu bir arıza değil, bağlantı durumunu da etkilemez:
  "bağlantı var" ≠ "sağlayıcı sağlıklı" (durum SAKLI veriden türetilir, sağlayıcıya çağrı yok).

## 1. Aşama — DB bağlantısına geçiş (Lale; bir kez, geri alınabilir)
1. Ayarlar → Bağlantılar → **"Mevcut bağlantıyı bu hesaba aktar"**. Bu düğme env token'ı org'un
   kendi kimlik bilgisi olarak DB'ye yazar (org kolonları + `ChannelConnection` satırı, tek TX;
   `hospitable.connect` audit satırı). Env değişkeni yerinde kalır (ikinci aşamaya kadar).
2. Doğrulama (salt-okuma):
   ```sql
   SELECT status, "credentialSource" FROM (SELECT status, 'db' AS "credentialSource" FROM "ChannelConnection") x;
   SELECT count(*) FROM "ChannelConnection" WHERE status = 'active';   -- 1 beklenir
   SELECT ("hospitableTokenEnc" IS NOT NULL) AS own FROM "Organization" WHERE id = '<PRIMARY_ORG_ID>';
   ```
   Ayarlar sayfası artık "Bu hesabın kendi Hospitable bağlantısı" demeli (`state: connected`).
3. **Provenance'a etkisi:** bu andan itibaren YENİ ingest satırları `connectionId` + `connectionEvidence=ingest`
   taşır; senkron penceresinde (90/540 gün) yeniden gözlenen legacy satırlar `observed` olur. Pencere
   dışı legacy satırlara DOKUNULMAZ (çıkarım backfill'i yok, tasarım gereği).
4. Geri alma: Ayarlar → "Bağlantıyı kes" → org kolonları temizlenir, satır `disconnected`; env fallback
   hâlâ set olduğu için Lale erişimi kesilmez (`state: disconnected` + `envAvailable`).

## 2. Aşama — Okuma anahtarı (`CHANNEL_CONNECTION_READ=1`), ≥2 hafta gözlem
Ön koşullar: Aşama 1 tamam; şu parite sorgusu 0 dönmeli (dual-write kanıtı):
```sql
SELECT count(*) FROM "ChannelConnection" c JOIN "Organization" o ON o.id = c."organizationId"
WHERE c.provider = 'hospitable' AND c.status = 'active' AND c."accessTokenEnc" IS DISTINCT FROM o."hospitableTokenEnc";
```
Açılış: Railway → Variables → `CHANNEL_CONNECTION_READ=1` (yeniden deploy). Açıkken satır otorite;
satırı olmayan org kolona düşer; env fallback aynen (test-pinli: `connection-state.test.ts`, her senaryo
anahtar açık/kapalı ikisiyle koşar). Sorun olursa env'i sil → anında eski davranış.
Gözlem listesi (2 hafta): senkron sayaçları (`/api/health?strict=1`), oto-yanıt/karşılama gönderimleri,
`MessageOutbox` `lastErrorCode='connection_inactive'` sayısı (0 beklenir; >0 ise bir bağlantı revoked/
disconnected iken kuyrukta mesaj var demektir — Ayarlar'da yeniden bağlanılır).
